# Project notes for the agent

- AGENTS.md lists the idiosyncrasies of the data and the logic (the REST's row cap, the 1917-18 defaulted games, the non-NHL Finals, the 2026 franchise re-ruling, each stat's floor). Read it before changing the harvester, the builder or the engine, and add to it when a gate or a reader teaches us a new one. The research that decided the era wall is `research/README.md` and `research/beachhead.md`.

- What it is: a query engine for NHL career-point comparisons ("Connor McDavid has 1,000 points through his first 659 games"). A reader sets a five-slot sentence (who · did what · how much · over which games · against whom) and the board ranks every career, or every player-season, by its value at that window. It is the NFL Comparator (`~/Projects/nfl-comparator`) and WNBA Comparator (`~/Projects/wnba-comparator`) over hockey, with one change forced by the size of a century of games: the ledger is columnar.
- Data: the NHL's own game records through its public stats REST (`api.nhle.com/stats/rest/en`), 1917-18 to the running season. `npm run harvest` (`pipeline/harvest-rest.mjs`) fills `data/raw/` (gitignored) through `research/lib/fetch.mjs` (one request per 1.5 s, cached forever; about 960 requests for everything, the skater report windowed by game id under the REST's 10,000-row cap). `npm run ledger` (`pipeline/build-ledger.mjs`, offline) writes `src/data/skaters.json` and `src/data/goalies.json` (committed; the site builds without the cache): per player, every game he dressed for, each column packed as a string (`src/lib/pack.ts`), with the result, the team's game number that season (`tgn`) and the line; `src/lib/ledger.ts` decodes them into typed arrays. Known-answer gates in the builder (Gretzky's 39th game, Richard's 50th, Lemieux's 44th and 46th, Howe 1952-53, Orr +124, McDavid 659, Ovechkin 1,487, Brodeur 691, the stat floors) run before the write. Birth dates are Wikidata's (`pipeline/fetch-people.mjs` → `data/ref/people.json`). `npm run refresh` refetches the running season and rebuilds; the daily cron in `deploy.yml` runs it in the runner, nothing committed back.
- Rulings the words rest on (also in `Notes.jsx`): a game is one the player dressed for (0-point games included; no TOI before 1997-98); a start exists for goalies only; a win is a goalie's decision, and an overtime or shootout loss is its own result (`result` 3, `dec` 3; folded into losses before 2005-06); "team games of a season" count the team's schedule from opening night (the record book's window for 50-in-50: Lemieux 1988-89 reads 46 here, 44 by his own games); regular season by default, `scope=all` adds the playoffs, never summed silently; each stat starts the season the league recorded it (`ledger.floors`; `statFloor`), a career that began before a stat's floor sits out its career fields, and the board says how many (`board.gapped`); WHA games, All-Star games (type 4) and the 1918-26 Finals against non-NHL teams are out; the 2020 qualifying round is playoffs; team codes are the codes of the day; ranks are competition ranks with ties.
- The gate is `src/lib/query.test.ts` (Vitest) and `scripts/gate.mjs` prints the same boards; `data/gates/factoids.json` (built by `npm run gates` from the research) is the 70-claim corpus still to be wired as assertions. Add a gate for every factoid the site is asked to reproduce, with the publisher's definition noted where it differs.
- Code layout: `src/lib` is TypeScript (`npm run typecheck` runs the root tsconfig and the worker's). `query.ts` is the engine (`evaluate` → ranked rows, the ones still inside the window, the gapped count and the board's era; `rowGames` materializes a row's games for the panel; `curve`, `crossings`, `toMatch` are the peer readings), `stats.ts` the catalog (noun, columns, thresholds, maxes for "N or fewer", `isUnit` for "a hat trick"), `words.ts` every sentence, `share.ts` the words a link carries, `compare.ts` the panel's reading, `url.ts` the query in the URL (one param a slot, defaults omitted, `t` the open row, `vs` the peer), `landing.ts` the named boards at their own paths. Components JSX; `Picker.jsx` and `Icons.jsx` are Streak King's.
- Look and page anatomy: the siblings' (dark stadium palette, Graduate numbers, Source Serif words, Plex Mono labels, dashed-underline pickers; dateline with finder, Ko-fi and share; h1; the sentence; the board with the panel inline; Questions; What to read next; the citing ask; Method; footer).
- Vite + React static site for GitHub Pages under drewhoover.com. `package.json` "name" is the slug and equals the repo name; `npm run build` builds the finder index (and `src/data/floors.json`, the stat floors the Method reads), the records mine (`scripts/build-records.mjs`: `public/players/<id>.json`, gitignored), the bundle and the prerender (`scripts/prerender.mjs`: the root, one page per landing, a page and card per player at `player/<id>/`, a page and card per franchise and position at `team/<abbr>/<forwards|defensemen|goalies>/` plus the `team/` index, sitemap, llms.txt, the ledger copies for the worker). `main.jsx` routes by path: a player or team page imports only its own component and its embedded data, never the ledgers. The player pages are the NBA Comparator's (`records.ts`, `PlayerPage.jsx`, `?tune=1` for the knobs; the rulings are the NFL Comparator's `specs/player-pages.spec.md`); the team pages are the College Football Comparator's (`groups.ts`, `GroupPage.jsx`). The share worker (`workers/share/`) is the WNBA one over two ledgers: it loads skaters or goalies by the query's field and draws the board, or with `t=` (and `vs=`) the NFL Comparator's comparison card; `SAFE` is the 720px column; `CARD_VERSION` keys the edge cache; deploys from `deploy.yml` with `CLOUDFLARE_API_TOKEN`.
- Dev server: `npm run dev` (port 5177 in `.claude/launch.json`); `npm run records` first for the finder and the player pages. The team pages exist only in the prerender (their data is embedded), so check them with `npm run build` and `npx vite preview`. Tests: `npm test`. Images: `npm run gen:favicon`, `npm run gen:og` (Georgia Bold from the Mac).
